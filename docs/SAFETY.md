# 安全模型

## 两类清理入口

任务清理与全局存储清理使用不同的规则和执行器。任务清理只处理一个明确任务树及其关联资源；存储清理处理 Codex 的共享缓存、临时项、备份和日志。任务分析发现的共享或全局数据只能跳转到存储入口，不能在任务入口直接删除。

## 任务关系

删除集合只由所选根任务和 `parent_id` 递归得到的后代组成。同名任务、同一工作目录任务、重试任务和分叉任务只用于筛选与提示，不自动加入删除集合。

本地任务清单只接受 `sessions` 与 `archived_sessions` 中真实存在的 canonical transcript；旧 `session_index.jsonl` 中没有 transcript、状态数据库记录或官方任务的条目只产生告警，不作为任务展示，也不计入可释放空间。迁移备份中的 rollout 由存储扫描单独列为人工复核，避免与真实任务重复计数。

官方 `thread/delete` 负责删除根任务及派生后代的持久化任务数据。界面在确认前列出任务数、子任务数和全部 transcript 大小。该部分属于永久删除。所有根任务和子任务 transcript 都交给官方接口处理，不再先当作普通文件移入回收站，也不重复计算可清理字节。

删除请求返回成功后，软件通过官方 `thread/list` 重新枚举活跃与归档任务，并重新检查计划中的 transcript 路径。仍有任务索引、transcript，或校验接口失败时，回执标记为“部分完成”，界面不会乐观移除对应任务。

## 资源归属

- `专属`：结构化事件、任务 UUID 目录、补丁或明确输出参数能够证明资源属于该任务。
- `共享`：同一资源被其他任务使用，或属于随机 UUID 附件等不能按任务直接移除的数据。
- `全局`：Codex 数据库、索引、公共日志、缓存或状态。
- `未知`：只证明任务曾引用路径，不能证明创建者和唯一所有者。

工具输出里观察到的现存路径属于弱证据：它能补全“过程中碰过哪些文件”，但不能单独证明文件由任务创建，因此默认未知归属且不会自动删除。达到分析上限时必须显示告警，未分析内容不会进入清理计划。

软件建议与用户选择分别保存。批量规则不会把未知、共享或全局资源改成删除；用户显式选择未知单个路径时会记录覆盖选择，并在执行前再次校验。

## 成果阶段

- `最终成果`：具有明确交付、定稿、发布证据，且不位于测试、QA、审计、预览或渲染过程路径。
- `过程成果`：草稿、预览、渲染、测试、QA、审计、缓存版本，或位于 Codex 操作目录但没有独立交付证据的生成文件。
- `待判定`：已确认是成果类型，但证据不足以判断是否定稿。

最终成果默认保留。过程成果默认复核；只有归属为专属的过程成果会进入安全批量选择。

## 路径执行检查

文件清理统一进入 Windows 回收站，并在执行瞬间检查：

- 路径必须为绝对路径，且不能是盘符根目录。
- 不跟随或清理符号链接、junction 和其他重解析点。
- 待删父目录若包含标记保留、复核或受保护的后代，计划被阻止。
- 父子目标去重，计划可回收量按互斥路径计算；文件进入回收站后需清空回收站才释放磁盘空间。
- 共享和全局资源不能由任务清理执行。
- Codex 运行期间不执行全局存储清理。

## 全局存储规则

`退出 Codex 后安全`只表示内容可重新下载或重建，不表示立即自动选择。扫描始终保持只读；用户点击一键规则后，仅选择至少 7 天未更新的可重建缓存和临时项。以下类别不会被一键选择：

- 活跃及归档任务记录；
- SQLite、WAL、SHM、索引和全局状态；
- 登录态与浏览器持久数据；
- Codex 运行组件、插件和技能；
- 迁移备份、诊断日志、附件和用户资产；
- 未被 `current` 指针引用的旧 CLI 发布包、内容地址更新目录和本机运行组件副本；这些项即使很旧也只能人工复核；
- 最终成果、源码、支持库及证据不足的过程成果。

Windows 应用包本体由 Windows 和 Microsoft Store 管理，本工具不进入 `WindowsApps` 删除旧包。CLI 发布包只在能解析 `packages\standalone\current` 时才标记“当前”或“旧版”；无法证明时一律保护。

## 操作记录

预览和执行记录均使用带毫秒及进程 ID 的唯一文件名。即使验证或部分操作失败，也会保存结果、失败原因和实际处理路径，便于核对与恢复。
